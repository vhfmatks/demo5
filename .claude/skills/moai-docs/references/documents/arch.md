# `docs/arch.md` — 어떻게 구성했나요?

설계·구현 구조·배포·복구를 작성하거나 코드와 대조할 때만 읽는다. 제공된 문서 레이아웃을 따르고 기존 문서의 선택 이유·이력은 보존한다.

**작성·갱신 시점:** 설계할 때 선택 이유를 적고, 구현·배포 후 코드와 실제 흐름에 맞춘다.

**본문 배치:** 구성·기술 선택 이유 → 입력 → 처리 → 저장 → 응답과 소스 위치 → 데이터·API·권한 경계 / mock 구분 → 의존성·배포·재시작 / 복구 → 제약.

- 흐름·소스 표: `REQ·FLOW | 입력 | 처리 | 저장 | 응답 | 소스 위치`.
- 경계 표: `데이터·API·화면 | 권한 경계 | 실제 / mock | 관련 REQ | 소스 위치`.
- 운영 표: `의존성·배포 단계 | 실행·재시작·복구 방법 | 선택 이유 | 제약`.

schema·service·route·화면·배포 설정과 대조한다. 요구 계약은 PRD, 변경 과정은 development, 실제 시험 결과는 e2e-test로 연결한다. 구조 변경의 검증 영향까지 판정할 때만 [라이프사이클](../lifecycle.md)을 추가로 읽는다.
