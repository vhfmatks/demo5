# `docs/experience.md` — 사용자는 어떻게 경험하나요?

사용자 흐름·관찰 결과·효과를 작성·갱신할 때만 읽는다. 제공된 문서 레이아웃을 따르고 기존 문서의 FLOW·실제 관찰 이력은 보존한다.

**작성·갱신 시점:** 구현 전 사용 순서를 정하고, 구현 후 화면·출력·저장 결과로 확인한다.

**본문 배치:** FLOW-01 → 요구 · 시험 연결 → 정상 / 오류 / 빈 상태 / 권한 / 복구의 사용 순서 → 실제 화면·출력·저장 결과 → 관찰·비교한 가치와 한계.

- 흐름 표: `FLOW | REQ·AC | 사용자 | 호출·입력·단계 | 응답·화면・저장 결과 | TC | 근거·상태`. FLOW ID는 `FLOW-NN`(기존 최고 번호 다음, 재사용·재번호화 금지)이며 spec(G2)이 붙이고 PRD AC 표의 FLOW 열에 같은 ID를 적는다.
- 효과 표: `FLOW | 비교 대상 | 확인·측정 방법 | 실제 결과 | 예상 / 관찰 / 미측정 | 근거·한계`.

API·CLI는 호출 · 입력 · 응답으로 설명한다. 구현 전 출력·화면은 계획이고 구현 후 실제 결과와 구분한다. 수치·비교 방법이 없는 효과는 예상·미측정으로 남긴다. FLOW·AC·TC 연결이나 판정이 바뀔 때만 [라이프사이클](../lifecycle.md)을 추가로 읽는다.
