# `docs/security-compliance.md` — 보안 기준을 어떻게 지켰나요?

공식 SEC별 적용·검증·위험·예외를 작성·갱신할 때만 읽는다. 제공된 문서 레이아웃을 따르고 기존 문서의 SEC·실행 이력은 보존한다.

**작성·갱신 시점:** 정책 수령·개정, 보안 코드 변경·리뷰·시험 후 적용 여부와 실제 결과를 갱신한다.

**본문 배치:** 주최 측 정책 기준·수령 상태 → SEC 항목별 적용 이유·코드 위치·시험 결과 → 정상 요청 성공·잘못된 요청 거부·저장값 확인 → 미적용 / 해당 없음 / 예외 / 미검증의 이유·위험·검토 상태.

- 준수 표: `SEC | 적용 여부·이유 | 코드 위치 | TC·검증 방법 | 실제 결과·근거 | 위험·예외 | 검토 상태`.

**G2 계획**: `docs/security-policy.md`가 있으면 공식 SEC마다 한 행(적용/해당 없음과 이유, 계획 적용 위치, TC 또는 검증 방법, 상태 `미실행`, 제약·예외 없으면 `—`)을 쓰고 각 `SEC-KIT-*` 행을 공식 번호로 옮긴 뒤 지운다. 정책이 없으면 `SEC-KIT-*`를 유지하고 이 프로젝트의 TC를 맞는 행에 더하며 상태 `미실행`, 아직 공식 매핑 전임을 사용자에게 알린다.

공식 SEC → 구현 → TC → 소스 SHA·결과를 연결한다. 임시 SEC를 공식 번호로 바꾸어 쓰지 않는다. 권한 계약은 PRD, 강제 구조는 arch, 재현 절차는 e2e-test로 연결한다. 상태 판정·보안 변경의 재시험은 [라이프사이클](../lifecycle.md), 원문 수령·보존은 [security-policy](security-policy.md)를 필요한 경우만 읽는다.
