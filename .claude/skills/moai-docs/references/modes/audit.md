# 문서·실행 근거 연결 감사

## audit (수시, 읽기 전용 연결 감사)

[라이프사이클](../lifecycle.md)을 읽고 관련 REQ·AC·문서·실행 근거를 대조한다. 특정 문서 레이아웃·표·TC 세부 검사가 필요할 때만 해당 `../documents/<문서>.md`를 추가로 읽는다. 전체 매뉴얼을 미리 로드하지 않는다.

다음 누락·불일치만 보고하고 코드·문서·GitHub 상태를 자동 변경하지 않는다.

- 필수 문서·정책 수령 여부와 README 문서·명령·근거 링크가 실제 파일·설정과 맞는가?
- 포함 REQ마다 AC가 있고 AC마다 Issue·FLOW(적용되는 흐름)·단위/상응 API/UI TC가 연결되는가? 제외·미구현은 이유가 있는가?
- e2e-test §2의 REQ/AC·TC·GIVEN/WHEN/THEN·경계·예상·파일과 실제 시험 제목·assertion이 맞는가? 정상·오류·권한·재조회가 적용되는 범위에서 빠지지 않았는가?
- 검증 AC의 모든 필수 TC가 실제 소스·시각·환경·명령·근거에서 PASS인가? 단위 전체 PASS·PR 보고·과거 결과만으로 검증한 곳은 없는가?
- 정책 SEC·코드·정상/거부/저장값 결과·미적용 이유·위험·검토 상태가 연결되는가? 실제/mock·예상/관찰/미측정·팀 역할·AI 검토 근거를 구분했는가?
- 변경 후 영향 항목을 미검증으로 되돌리고 재시험했는가? 문서·근거가 제출 SHA에 있고 시험 C → D가 설명되는가?

출력은 `REQ/AC | 누락·불일치 | 소유 문서·근거 | 다음 조치` 표와 미검증 요약이다. 문제가 없으면 확인한 범위·근거와 함께 없다고 적는다. 지적만으로 기능 시험을 실행했다고 주장하지 않는다.
