# 릴리스 범위 동결

## freeze (G5, 릴리스 범위 동결)

[라이프사이클](../lifecycle.md)과 변경할 brief·experience의 문서 매뉴얼만 읽는다. 새 PR·실행 근거가 있으면 sync, 연결 확인은 audit의 해당 절차만 이어 읽는다. 다른 모드·문서 매뉴얼 전체를 미리 로드하지 않는다.

1. 워커 PC의 진행 중 Issue가 끝나면 루프를 중단하도록 안내한다(STOP 파일: `docs/agents/issue-tracker.md`).
2. 열린 READY / NEEDS_HUMAN Issue는 유지·제외 결정을 이미 받았으면 재사용하고, 미결정 범위만 확인한다. 승인된 제외는 tracker **Drop**으로 처리하고 PRD의 해당 AC를 이유와 함께 `미구현`으로 둔다. 닫을 spec은 승인된 tracker **Close spec** 절차를 따른다.
3. `docs/experience.md`: E2E UI 실행 또는 실제 캡처의 `docs/evidence/` 화면 근거를 연결한다. 효과는 수치·방법이 있을 때만 측정, 아니면 예상·미측정으로 남긴다. 남은 한계에는 제외·미검증을 적는다.
4. `docs/project-brief.md`: 계획 대비 실제 제공 범위·항목별 선택 이유·구현 상태를 PRD와 대조한다. 관찰한 가치는 experience의 실제 결과를 짧게 요약하고 근거 링크·한계를 붙인다. 미관찰은 `미검증(관찰·측정 미실행)`으로 유지하며 예상과 섞지 않는다. 팀원 3명의 현재 역할·변경 이유·제약도 확인한다. 빈칸은 미정·미검증으로 명시하고 상세 AC 판정·측정 기록은 원본 문서에 둔다.
5. 미반영 PR·새 실행 근거가 있으면 sync하고 audit으로 필수 AC·TC·SEC·문서 연결을 확인한다. 동결 시 미구현·실패·미검증은 숨기지 않는다. 승인된 경우에만 관련 문서를 `docs: G5 freeze`로 커밋·push한다.
